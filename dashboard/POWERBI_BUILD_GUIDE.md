# Power BI Dashboard — Build Guide

> **Note on `.pbix` files:** Power BI Desktop files are a binary format that can only be created inside the Power BI Desktop application — they can't be generated by a script. This guide gives you everything needed to build `Ecommerce_Intelligence.pbix` yourself in under an hour: the exact data source, model relationships, and every DAX measure, ready to copy-paste.
## 1. Connect to the data

Open Power BI Desktop → **Get Data → ODBC/SQLite** (or, simplest: use **Get Data → Text/CSV** and import each file from `data/processed/`, since SQLite's native connector setup varies by machine).

**Recommended approach for reliability:** import these 8 CSVs from `data/processed/` as separate tables, plus the 2 feature-engineered CSVs:
- customers.csv, products.csv, orders.csv, order_items.csv, payments.csv, returns.csv, marketing.csv, website_events.csv
- rfm_segments.csv, cohort_retention.csv

## 2. Build the data model (relationships)

In Model view, create these relationships (all should default to the correct direction — verify each):

| From | To | Type |
|---|---|---|
| order_items[order_id] | orders[order_id] | Many-to-one |
| order_items[product_id] | products[product_id] | Many-to-one |
| orders[customer_id] | customers[customer_id] | Many-to-one |
| payments[order_id] | orders[order_id] | Many-to-one |
| returns[order_id] | orders[order_id] | Many-to-one |
| returns[product_id] | products[product_id] | Many-to-one |
| website_events[customer_id] | customers[customer_id] | Many-to-one |
| website_events[product_id] | products[product_id] | Many-to-one |
| rfm_segments[customer_id] | customers[customer_id] | One-to-one |

**Marketing is intentionally NOT related** to orders/customers (no shared key) — this mirrors real-world attribution ambiguity. Display marketing visuals on their own page using `marketing` directly.

Also create a **Date table** (Model view → New Table):
```dax
DateTable = CALENDAR(DATE(2023,1,1), DATE(2025,12,31))
```
Mark it as a Date Table (Table tools → Mark as Date Table), then relate `DateTable[Date]` to `orders[order_date]` (many-to-one, DateTable on the "one" side).

## 3. DAX Measures

Create a new Measures table (Modeling → New Table → `Measures = {1}` as a placeholder), then add:

```dax
Total Revenue =
SUMX(
    FILTER(order_items, RELATED(orders[order_status]) = "Completed"),
    order_items[quantity] * order_items[unit_price] * (1 - order_items[discount])
)

Total Cost =
SUMX(
    FILTER(order_items, RELATED(orders[order_status]) = "Completed"),
    order_items[quantity] * order_items[cost]
)

Total Refunds = SUM(returns[refund_amount])

Net Revenue = [Total Revenue] - [Total Refunds]

Total Profit = [Total Revenue] - [Total Cost]

Gross Margin % = DIVIDE([Total Profit], [Total Revenue], 0)

Total Orders =
CALCULATE(
    DISTINCTCOUNT(orders[order_id]),
    orders[order_status] = "Completed"
)

Total Customers = DISTINCTCOUNT(customers[customer_id])

Purchasing Customers =
CALCULATE(
    DISTINCTCOUNT(orders[customer_id]),
    orders[order_status] = "Completed"
)

AOV = DIVIDE([Total Revenue], [Total Orders], 0)

Total Units Sold =
CALCULATE(
    SUM(order_items[quantity]),
    orders[order_status] = "Completed"
)

Total Units Returned = SUM(returns[returned_quantity])

Return Rate % = DIVIDE([Total Units Returned], [Total Units Sold], 0)

Repeat Customers =
VAR OrderCounts =
    ADDCOLUMNS(
        VALUES(orders[customer_id]),
        "@NOrders", CALCULATE(DISTINCTCOUNT(orders[order_id]), orders[order_status]="Completed")
    )
RETURN
    COUNTROWS(FILTER(OrderCounts, [@NOrders] >= 2))

Repeat Customer % = DIVIDE([Repeat Customers], [Purchasing Customers], 0)

Customer Lifetime Value (Observed) = DIVIDE([Total Revenue], [Purchasing Customers], 0)
-- Note: this is an average observed CLV, not a predictive model. Label any
-- visual using this measure clearly as "Observed / Historical CLV".

Revenue Growth % =
VAR CurrentRev = [Total Revenue]
VAR PriorRev = CALCULATE([Total Revenue], DATEADD(DateTable[Date], -1, MONTH))
RETURN DIVIDE(CurrentRev - PriorRev, PriorRev, BLANK())

Marketing Spend = SUM(marketing[spend])

Marketing Attributed Revenue = SUM(marketing[attributed_revenue])

ROAS = DIVIDE([Marketing Attributed Revenue], [Marketing Spend], 0)

Conversion Rate % =
VAR Purchases = CALCULATE(DISTINCTCOUNT(website_events[session_id]), website_events[event_type]="purchase")
VAR Visits = CALCULATE(DISTINCTCOUNT(website_events[session_id]), website_events[event_type]="site_visit")
RETURN DIVIDE(Purchases, Visits, 0)
```

## 4. Page-by-page build

### Page 1 — Executive Overview
- KPI cards: `[Total Revenue]`, `[Total Profit]`, `[Gross Margin %]`, `[Total Orders]`, `[Purchasing Customers]`, `[AOV]`, `[Return Rate %]`
- Line chart: Revenue by month (`DateTable[Date]` on axis, `[Total Revenue]` as value)
- Bar chart: Revenue by category
- Card/callout: any KPI outside expected range (e.g. conditional formatting on Gross Margin % card, red if < 30%)

### Page 2 — Sales & Revenue
- Line chart: Monthly revenue + `[Revenue Growth %]` on secondary axis
- Bar chart: Revenue by category, by channel, by country
- Card: AOV, Total Orders
- Slicer: Date range, Category, Channel

### Page 3 — Customer Intelligence
- Cards: Total Customers, Repeat Customer %, `[Customer Lifetime Value (Observed)]`
- Bar/pie: `rfm_segments[segment]` by count and by sum of `monetary`
- Table: top customers by `monetary` (from rfm_segments)
- Matrix/heatmap: `cohort_retention.csv` — cohort_month (rows) x period_number (columns)

### Page 4 — Product Intelligence
- Table: top/bottom products by revenue and profit
- Scatter chart: Revenue (x) vs. Margin % (y) per product — recreates the opportunity matrix from `sql/04_product_analysis.sql`
- Bar chart: Return rate by category

### Page 5 — Marketing Performance
- Cards: Marketing Spend, `[ROAS]`
- Bar chart: ROAS by channel (conditional formatting: red below 1.0)
- Table: campaign-level spend/conversions/attributed_revenue

### Page 6 — Website Funnel
- Funnel visual: `event_type` ordered site_visit → product_view → add_to_cart → checkout_start → purchase, measure = distinct `session_id` count
- Bar chart: Conversion rate by device, by traffic_source

## 5. Design checklist (from Stage 22 requirements)
- [ ] Consistent color theme (suggest: navy `#1a3d5c` primary, light blue `#8a9fb5` secondary — matches the report branding)
- [ ] KPI cards use consistent formatting (currency, %, whole numbers as appropriate)
- [ ] No 3D charts, no unnecessary decorative visuals
- [ ] Slicers for Date, Category, Channel on relevant pages
- [ ] Tooltips added to key visuals (e.g. show margin % when hovering over a revenue bar)
- [ ] Page navigation buttons or tabs at top of each page

Once built, export a screenshot of Page 1 to `screenshots/dashboard.png` and save the file as `dashboard/Ecommerce_Intelligence.pbix`.
